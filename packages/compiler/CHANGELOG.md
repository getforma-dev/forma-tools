# Changelog

## [Unreleased]

### Fixed
- **Every `.tsx` page compiled to placeholder IR.** esbuild rewrites `export function Page() {…}` into `function Page() {…}` + `export { Page };`, and all three copies of "find the function this module exports under this name" read only `ExportNamedDeclaration.declaration` — the one form esbuild never emits. So a JSX root page resolved to nothing, `generateRealIr` returned null, and the plugin fell back to `<div id="app" data-forma-page="…"></div>`: no slots, no islands, zero server-rendered content, build exit code 0. The single line it printed (`could not find return h() tree in Page`) named the wrong cause and did not mention the consequence. The three copies (`parseComponentFile`, `findExportedFunctionBody`, `resolveSubComponent`) are now one resolver (`src/export-resolver.ts`) that handles declaration exports, export SPECIFIERS (`export { X }`, `export { XImpl as X }`, and specifiers forwarding an imported binding), `export default`, cross-file re-exports (`export { X } from './x'`, `export * from './x'` — index barrels), aliased imports at the call site (`import { CardImpl as Card }`), and — for same-file calls only — non-exported and function-scoped declarations. See *How a component is found* in the README for the full table, including the forms that are deliberately NOT followed and warn instead.
- **`.tsx` islands silently lost their signal defaults.** The same blind spot in `findExportedFunctionBody` had no warning at all: byte-identical `Counter.ts` and `Counter.tsx` islands produced different IR — the `.ts` one a named `hits` slot with default `"42"`, the `.tsx` one an anonymous `text:0` with no default — and nothing in the build log said so. Server-side injection by name then failed at runtime. An unresolvable component now warns; and when a barrel forwards the export, module-scope signals are read from the file that actually declares it rather than from the barrel.
- **Components imported by a PAGE file were invisible.** The import map was built once from the ENTRY point and captured in a closure that every nested walk carried unchanged (walk contexts are spread-copied), so a component `pages/OverviewPage.tsx` imported became an empty island shell unless `app.tsx` happened to import it too. `WalkContext.resolveComponent` now takes the file the CALL is in and rebases on that file's imports.
- **`mount(() => h('div', …), '#app')` dropped the whole page to placeholder IR.** `h` is an imported identifier, so the named-component pattern claimed it and the plugin went looking for a component file called `formajs`. An expression-bodied `mount()` arrow is now an inline mount, whose body is the tree — as is `mount(() => LocalPage(), '#app')` over a component declared in the entry file.
- **An inline-mount entry got ZERO named signal slots.** The plugin asked `extractSignalDefaults` for an exported function literally named `__inline__`, a lookup that could never match, so module-scope `createSignal`s on a `mount(() => { … })` page never became named slots and every binding to them landed in an anonymous `text:`/`attr:` slot that `SlotData::from_json` cannot address. Module-scope and mount-callback signals are now both collected (`extractInlineMountSignalDefaults`).
- **A numeric signal on an inline-mount page lost its type and default.** The two mount paths carried separate copies of slot registration and the inline one handled only text and bool, so `createSignal(11)` became a `TYPE_TEXT` slot with empty `default_bytes`. Both paths now share one registration.
- **Fragment children that were not `h()` calls or string literals were silently DROPPED** — `h(Fragment, null, h('p', null, 'a'), () => name())` emitted the paragraph and nothing else: no opcode, no island marker, no warning, and no way for the client to recover the missing binding because there was no marker to hydrate. Dynamic text, numbers, ternary shows, `createShow`/`createList` calls and spreads were all affected, in both the `h(Fragment, ...)` and bare `Fragment(...)` forms. Fragment children now go through the same `emitChild` path as an element's children, and a parameterised test requires the two to emit identical opcodes.
- **A component tag (`h(Card, ...)`, which is what JSX compiles `<Card/>` to) produced an ANONYMOUS island** — `island_0`, discarding the component name. Since the client registry is keyed by component name, that island could never hydrate: the page was left with a permanently empty `<div>`. Capitalized identifier tags now route through the same sub-component/island path as a `Card(...)` call, so they are inlined when resolvable and registered under their real name when not. Lower-case identifier tags (a runtime tag name) still emit a dynamic-tag island, now with a warning.
- **Call-site props were never substituted into an inlined sub-component.** The helper that claimed to do it returned its input unchanged on every path, so `Badge({ label: 'New' })` over `function Badge(props) { return h('span', null, props.label) }` inlined the span and then emitted an empty island where the label should be — the text absent from the server render with no diagnostic. Literal props are now substituted for both binding forms (`props.label` and destructured `{ label }`, including `{ label = 'fallback' }`), in attribute and child positions, skipping any name a nested function rebinds.
- **The static spread unroll (Rule 9) never substituted item properties in ATTRIBUTE position.** `...NAV.map(item => h('a', { href: item.href }, item.label))` substituted the label but passed the props object through untouched, so every row rendered `<a>` with the href missing and a slot that no runtime data would ever fill — the same silent missing-attribute shape as ledger finding #10. Substitution now descends into object expressions.
- **`formaCompiler`'s include/exclude patterns did not match anything they claimed to.** Exclude tested `id.includes(pattern.replace(/\*\*\//g, ''))`, i.e. `id.includes('node_modules/**')`, which is false for every path that exists — so the default exclude never excluded and the plugin rewrote dependency sources. Include compared only the pattern's file extension, so a scoped `include: ['src/**/*.ts']` also claimed `vendor/x.ts`. And Windows module ids (backslash-separated) matched no pattern at all. Both are now real anchored glob matches (`**` = any number of segments, `*` = within a segment) over an id normalized to `/` with any Vite query suffix stripped. Projects that were relying on `.js`/`.jsx` being transformed must list them in `include` — the documented default has always been `.ts`/`.tsx` only.
- **An island subtree that threw mid-walk left the bytecode unbalanced** — `ISLAND_START` had been emitted, and the failure path registered a *second* island and emitted a nested shell instead of closing the first. The failure is now absorbed inside the span: the diagnostic names it and `ISLAND_END` still closes the island.

- **Duplicate `attr:` and `text:` slot names on any page that binds the same attribute key twice, or has two dynamic text children at the same child index** — the per-page `#n` occurrence registry introduced for list and show slots was never extended to the other two slot-name families. `h('div', { id: () => a() }, h('span', { id: () => b() }))` emitted two slots both named `attr:id`; two sibling `<span>`s each with a single dynamic text child emitted two slots both named `text:0`. The Rust loader builds `name_to_slot: HashMap<String, u16>` by inserting every name (`forma-ir/src/slot.rs`), so duplicates collapse last-insert-wins and the earlier slot becomes permanently unreachable for server-side `SlotData` injection — silently, with no build error. `attr:` and `text:` now run the same page-wide occurrence registry as list and show, created eagerly on the root walk context and shared by reference into island subtrees, inlined sub-components, list bodies and show branches. First occurrence keeps its exact former spelling (`attr:id`, `text:0`); later ones get `#2`, `#3`. See the migration note in the README — server code that injected a duplicated key was addressing the LAST occurrence and must now use the suffixed key for it.
- **Duplicate slot names when the first list/show sat inside a nested walk context** — the per-page list/show name registries were created lazily on the *current* context, but island subtrees, inlined sub-components, and list bodies walk spread copies of it. If the first `createList`/`createShow` for a given base name lived inside such a copy, the registry died with the copy and a later sibling recreated it, minting duplicate names (`list:todos:array` twice, `show:visible` twice) that collapse in the Rust name→id map (last-insert-wins) — and the outcome was document-order dependent. Registries are now created eagerly on the root walk context and normalized at the walk entry points, so suffixes (`#2`, ...) are page-wide in document order regardless of nesting.
- **Island slot-capture stack now stays balanced when an island subtree walk throws** — a resolution failure mid-walk used to leak the capture set, making an enclosing island record the failed inner island's (wrong) slot ids.
- **Per-item list scratch slots (`list:<base>:item`) are excluded from island `slot_ids`** — they hold the LAST rendered row after SSR, so serializing them into `data-forma-props` leaked that row into the page. All other families (named signals, `attr:*`, `text:*`, `show:*`, `list:*:array`, `list:*:<prop>`) are still captured; the key-space contract is documented in the README.
- **`export const` declarations are now visible to module-level extraction** — string-constant folding, file-constant arrays (Rule 9 unroll), and module-level island `createSignal` defaults previously only saw bare `const` statements and silently ignored exported ones.
- **Island signal-default conflict warnings name the actual declarer** — merging is first-wins, so the kept default may come from an *earlier island* rather than the root; the warning previously always credited the root.
- **Island signal defaults merge on the inline mount path** — entries using a block-body `mount(() => { ... return h(...); })` plus `activateIslands({...})` never merged island signals (and never populated island names at all); the `activateIslands` registry is now scanned on every entry-point pattern and the merge is shared between the named and inline paths.
- **Sub-component constant re-extraction falls back to empty maps on parse failure** — it previously fell back to the *parent* file's constants, resolving the child's identifiers against the wrong module scope.
- **`function` expressions derive binding names** — `createShow(function () { return visible(); }, ...)` now yields `show:visible` (previously silently positional); block-body arrows unwrap too. Applies to list sources as well.
- **Module consts shadowed in any nested scope are no longer folded** — a component-local `const cls = computeClass()` shadowing a module `const cls = 'icon'` used to bake the module value into a static attribute with no slot, unrecoverable client-side. Shadowed names now take the correctable dynamic-attribute path with the existing build warning. The check is deliberately over-conservative (any nested declaration or parameter of the same name suppresses folding).
- **64KB string guards** — a folded const over 65535 UTF-8 bytes is dropped from folding with a warning (FMIR string-table entries have a u16 length prefix), and the binary emitter now throws a descriptive error instead of silently wrapping the length and corrupting the string/slot tables; `generateRealIr` catches that and falls back to no-IR with a warning.

### Changed
- **Breaking: show slots now get condition-derived names** — every `createShow` previously emitted a slot literally named `show:createShow` (and ternary conditionals `show:<index>`), so at most one show per page was addressable by name. Shows now use the same naming scheme as lists: the base derives from the condition (`createShow(() => visible(), ...)` → `show:visible`; arrows, calls, member access, and `!`-negation unwrap), with a positional fallback (`show:#2`) and per-base `#n` occurrence suffixes in document order (first occurrence unsuffixed).
- **List slot names for literal sources now use the map parameter** — when the data source has no derivable name (e.g. `createList(() => [], ...)`), the map function's first parameter names the list (`(tile) => ...` → `list:tile:array`) instead of the positional `list:#N:array`; the positional fallback remains for `_`/unnamed params.
- **Migration**: server code injecting `"show:createShow"` must switch to the name-keyed scheme (`"show:visible"`); literal-source list keys change from `"list:#N:array"` to map-param-derived where a named param exists. Slot names are visible in the emitted `.ir` string table; unknown keys are silently ignored by `forma_ir::SlotData::from_json`, so stale keys fail soft — check names after upgrading.
- Sub-component and island subtrees now resolve file-level constants against their **own** module scope (re-extracted from the resolved source) instead of the root file's constants.

### Removed
- **Breaking: the SSR plugin no longer writes `<page>.islands.json`.** It was build metadata deposited into the *served* asset directory, unhashed, so it lingered in the output and was picked up by asset-embedding servers; its only consumer was `@getforma/build`'s island-registry generator, itself removed as unusable. The island table is inside the `.ir` binary, and `generateRealIr()` returns it as `{ binary, islands }` for programmatic callers.
- **`emitIr` is no longer exported** — it and its private `emitNode` helper were a second, divergent AST→opcode implementation with no consumer anywhere in this repo or the downstream ones: the real pipeline has always gone through `walkHTree`/`walkCallExpression`. `emitNode` predated the slot-name occurrency registries entirely (it minted raw `attr:<key>` / `text:<i>` names) and understood none of createShow, createList, islands, Fragments or sub-component resolution, so anything that had adopted it would have produced subtly wrong IR. Use `generateRealIr` (or `walkHTree` with an `IrEmitContext`) instead. `IrEmitContext` itself is unchanged and still exported.

### Added
- **Two FMIR corpus cases that mirror what a real project produces**, `jsx-page` (an all-`.tsx` app — entry, page, sibling sub-component and island, every one arriving through esbuild's export rewrite) and `barrel-exports` (every component reached through an `index.ts` barrel). Both were total losses before the resolver fix and neither could have been caught by the old suite: all 22 fixture files were `.ts`, `.tsx` appeared only as a hand-written filename label on already-transformed source, and no test anywhere asserted that emission had NOT fallen back to the placeholder. The Rust contract test (`resolution_cases_ship_named_islands_over_named_slots` in `forma`) requires their islands to carry real component names rather than a minted `island_<n>`, to carry non-empty slot ids, and the page to have slots named after its signals carrying their defaults — claims the golden HTML cannot make, because a degraded emit is still a valid, walkable module. The existing eight `.ir` files are byte-identical.
- **`tests/ssr-emission.test.ts`** — `generateRealIr` over real files on disk, which is the level the suite was blind at. Every assertion goes through a helper that first proves the emit is not the placeholder shell.
- **Build diagnostics for every silent degradation.** The pattern behind most of the ksx dogfood findings was "the compiler could not understand a construct, emitted a placeholder, and said nothing". Every fallback path now warns with the file, the construct in source terms, and the consequence for the rendered page: dynamic tags, untranslatable children (bare identifiers, template literals, unwrapped ternaries and `&&`), un-unrollable spreads, each `createList` bail-out, non-`h()` `createShow` branches, components that cannot be resolved / are recursive / exceed the inlining depth / are passed non-literal props / have no followable return, islands whose content will not compile, and `createSignal` initial values that are not literals (which is why the signal gets no named slot — ledger finding #9's cost, previously invisible). Diagnostics name the *resolved component's* file, not the page that included it. A page the compiler fully understands emits nothing, and a test enumerates the fallback call sites in the walker so a new one cannot be added without a diagnostic.
- **Island table entries now carry real `slot_ids`** — every slot referenced inside an island's SSR span (dynamic attrs, signal-bound text, list slots, reused page-level signal slots, nested islands) is captured and written to the island table, which was previously always empty. The `forma-ir` Rust walker skips props emission for islands with empty `slot_ids`, so with this populated it natively emits `data-forma-props` and the `__forma_islands` script block — consumers hand-emitting that script block server-side can migrate to the native path.
- **Signal defaults are extracted from island component files** — both module-level `createSignal` declarations and declarations at the top of the exported island function. Module-level declaration in the island file is now the recommended single-source pattern; Page twin declarations are no longer required. Merging is first-wins (root Page authoritative); a conflicting default warns at build time.
- **Module-level string constants fold into static attributes** — a top-level `const` initialized with a string literal, expression-less template literal, `+` concatenation chain, or reference to an earlier string const resolves at compile time when used as an attribute value (`d: ICON_PATH` → static attr, no slot), and folds inside function-valued props when computing SSR defaults.
- **Build warning for statically unresolvable identifier attributes** — an attribute value that is a bare identifier or member expression the compiler cannot resolve now warns at build time instead of silently rendering the attribute empty in SSR.

## [0.2.0] - 2026-08-05

### Changed
- **Breaking: list slots now get unique, per-list names** — previously every `createList` emitted slots named `list:array` / `list:item` / `list:<prop>`, so on pages with more than one list only the first was reachable by name and server-side `SlotData` injection could not target the others. Each list now derives a base name from its data source (`createList(todos, ...)` → `todos`; arrows, calls, and member access unwrap to the underlying name), deduped per page with `#n` suffixes and a positional fallback (`#3`) when no name is derivable. Slots are emitted as `list:<base>:array`, `list:<base>:item`, and `list:<base>:<prop>`.
- **Migration**: server code injecting `"list:array"` must switch to the named key, e.g. `"list:todos:array"`. Slot names are visible in the emitted `.ir` string table; unknown keys are silently ignored by `forma_ir::SlotData::from_json`, so stale keys fail soft — check names after upgrading.
